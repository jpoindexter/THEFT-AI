# UI Flow Contract: Founder Happy Path

## Mission Control

When a founder opens Mission Control after onboarding:

- Show a current objective derived from company context or starter task.
- Show a guided next-step panel when the company has setup gaps, no active output, or starter tasks only.
- Explain the workflow in product language: Operator routes work, departments produce output, Library stores durable artifacts, founder approves or revises.
- Keep runtime diagnostics secondary.
- Keep Operator accessible after collapse.

## Task Review

When a founder opens a task:

- If no Library output exists, show that output is missing and provide an Operator action to publish or explain it.
- If Library output exists, show the artifact title(s), provide a Library action, and allow approve/revise decisions.
- Do not present runtime completion as equivalent to founder-approved output.

## Onboarding

When a founder answers stage/interview prompts:

- Plain-language help must be available for confusing business prompts.
- A generated draft may be offered, but the founder remains in control of the final answer.
- After plan acceptance, the next screen must orient the founder before showing department/task density.
